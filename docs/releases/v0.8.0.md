This release opens RemoteApp programs and takes drops on their windows, keeps the agent from holding a RemoteApp session open, and can give the drives of your computer letters of the session.

## Why

Nearly all the sessions of the server I test with are RemoteApp sessions, and none of them had the agent: a RemoteApp session does not run the `Run` entry. I wrote the RemoteApp support from the documentation and from what the Remote Desktop control exposes. I could not test it against a real server before this release.

## What happens now

- A .rdp file with `remoteapplicationmode:i:1` opens a RemoteApp tab. The tab shows the name of the program, the state of the connection and of the agent, and the last drop result; the program opens in its own windows.
- A drop on a window of the program is replayed in the session where you released the button. The progress window, the fast transfer and the direct connection work as for a desktop. The program shows no drop feedback while you move.
- Closing the tab, or quitting, while the program has windows open asks first, since the program keeps running on the server.
- In a RemoteApp session the agent exits by itself once no program is left, so that the session ends as it does without the agent, and its tray icon never appears while `trayIcon` is `auto`. In a desktop session it looks once at start and changes nothing else.
- `--status` also says whether the session is a RemoteApp session, whether the agent is listed under `SysProcs` and whether its scheduled task exists.
- The new agent option "Client drives on drive letters", off by default, maps `\\tsclient\C` and the other drives of your computer to letters of the session while the client is connected, for you only.
- An administrator can set defaults for every user in `%ProgramData%\UltimateRDP\agent.json`; the agent.json of each user still wins, key by key.

## For administrators

The agent does not start in RemoteApp sessions by itself. The README gives the commands: a `SysProcs` value, then a scheduled task at logon for one test account, then for every user, with their removal. Please apply them in that order, and test on one account before the others. UltimateRDP itself never writes the registry and never creates a task.

## Upgrade

Install 0.8.0 on both sides. Do not start an agent 0.7.0 in RemoteApp sessions: it would keep them open after the program closed. Please send me both logs of a first RemoteApp session; the section "Version 0.8" of the design lists the log lines that tell what works.
