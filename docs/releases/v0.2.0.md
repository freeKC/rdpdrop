This is the second test release of RdpDrop. Files you drop on the session now reach the remote application under the cursor, not only Explorer. Version 0.1 worked in its first test against a real server, and this version builds on that test.

The release contains two zips, each with one executable:

- `RdpDrop.Client-v0.2.0-win-x64.zip`: the client you run on your own computer.
- `RdpDrop.Agent-v0.2.0-win-x64.zip`: the agent that runs in your session on the server.

## What changed since 0.1.0

**Native drops into applications.** While you drag over the client window, the agent replays the same drag inside the session as a real OLE drag and drop. Explorer, mail clients, browsers and business applications receive the files as a normal drop, and show their own feedback while you move. A banner at the top of the session says "Drop here to send the files into the session". The drag offers copy and link only, never move. When nothing under the cursor accepts the drop, the agent copies the files to the fallback folder, as in 0.1. Two new settings in the agent tray menu control this: "Stage files in the session before the drop", for applications that refuse network paths, and "Copy to the fallback folder when nothing accepts the drop".

**Display.** The View menu offers "Resize session to window", now the default, and "Scale to window", the 0.1 behaviour. It also has a scale factor, full screen with F11 or Ctrl+Alt+Pause, "Use all monitors", and the choice of where the Windows keys go. The client also reads more keys of the .rdp file: audio, printers, COM ports, smart cards, Windows keys, monitors and scale factor.

**Sessions and credentials.** Each session opens in its own tab. The File menu has Open .rdp, Recent, Reopen in new tab and Close tab. Before connecting, the client uses the generic credential `TERMSRV/<host>` from the Windows Credential Manager when there is one. RdpDrop never saves a credential. File, Forget saved credentials deletes the ones Windows keeps for the host.

**Packaging.** Each archive holds one portable executable, without debug symbols or extra files. Both executables run without administrator rights.

## Compatibility

A 0.2 client works with a 0.1 agent, and a 0.1 client works with a 0.2 agent. In both cases you get the 0.1 behaviour: a copy to the folder under the cursor. To get the native drop, update both sides.

## What I could not verify yet

I tested the live drag on a local desktop, with Explorer as the target. I have not yet run it inside a real Remote Desktop session. These points need your feedback:

**The live drag in a session.** If a drop does nothing, the client log has lines that contain "Drag enter", "Drag ack" and "Drop result". The agent log has lines for the same drag id, such as "proxy window over the virtual screen", "button pressed on the proxy window" and "dropping on".

**The first drop on Explorer.** It can take several seconds. Please tell me how long it takes for you, and whether later drops are faster.

**Drops in full screen.** The drop point is mapped to the area the session covers, one monitor or all of them. If a drop lands in the wrong place, the client log line for the drop gives the point in the view and in the session, and says "full screen".

**Saved credentials of the domain password type.** The "Remember me" box of the Windows prompt saves this type, and RdpDrop cannot read its password. If you have one, the client log says "Windows keeps a domain password credential". Please tell me whether the Windows prompt still fills it in for you.

## Install

1. On the server, exit the 0.1 agent if it runs, then unzip the agent to a folder every user can read, such as `C:\Program Files\RdpDrop`.
2. From an elevated prompt, run `"C:\Program Files\RdpDrop\RdpDrop.Agent.exe" --install-all-users`, or `--install` for your own account only.
3. On your computer, unzip the client anywhere. Make sure your .rdp file redirects drives (Local Resources, More, Drives).
4. Run `RdpDrop.Client.exe path\to\connection.rdp`, log on, wait for "Agent ready" in the status bar, then drag.

## Logs and feedback

Both logs are in `%LOCALAPPDATA%\RdpDrop\logs`: `client-yyyyMMdd.log` on your computer, and `agent-yyyyMMdd.log` on the server. The client opens this folder from Help, Open log folder, and the agent from its tray menu.

Please open an issue at https://github.com/freeKC/rdpdrop/issues and attach both log files. Tell me which remote applications you dropped on, and whether you connect through a gateway.

Thank you for taking the time to try RdpDrop.
