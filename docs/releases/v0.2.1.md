This release makes RdpDrop simpler. A drop now reaches the application under the cursor, or it is ignored.

The release contains two zips, each with one executable:

- `RdpDrop.Client-v0.2.1-win-x64.zip`: the client you run on your own computer.
- `RdpDrop.Agent-v0.2.1-win-x64.zip`: the agent that runs in your session on the server.

## What changed since 0.2.0

**Drops that nothing accepts are ignored.** When no window under the cursor accepts the files, the status bar says "Nothing under the cursor accepted the files." and nothing else happens.

**The agent never copies files on its own.** The copy to a fallback folder is gone. The tray menu no longer has "Fallback folder" or "Copy to the fallback folder when nothing accepts the drop", and `agent.json` no longer reads `fallback`, `customFolder` or `fallbackCopy`. "Stage files in the session before the drop" stays.

**Version 0.1 compatibility is removed.** The live drag is the only way a drop reaches the session. A 0.2.1 client does not work with an older agent, and a 0.2.1 agent does not work with an older client. Update both sides to 0.2.1.

## Install

1. On the server, exit the running agent from its tray menu, then unzip the new agent over the old one, for example in `C:\Program Files\RdpDrop`.
2. Start it again, or run `"C:\Program Files\RdpDrop\RdpDrop.Agent.exe" --install-all-users` from an elevated prompt for a first install, or `--install` for your own account only.
3. On your computer, unzip the client anywhere and run `RdpDrop.Client.exe path\to\connection.rdp`. Wait for "Agent ready (v0.2.1)" in the status bar, then drag.

## Logs and feedback

Both logs are in `%LOCALAPPDATA%\RdpDrop\logs`: `client-yyyyMMdd.log` on your computer, and `agent-yyyyMMdd.log` on the server. Please open an issue at https://github.com/freeKC/rdpdrop/issues with both log files, and tell me which remote applications you dropped on.
