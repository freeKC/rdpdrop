This release sends files from the session to your computer through the direct connection, opens a RemoteApp program from a shortcut with only its own windows on the screen, and can ask for the password at every connection.

## Why

You asked for the other direction with the rate of the first one. A drag out of the session is not possible with RDP, so the session sends files with its Send To menu, and the direct connection of 0.7 carries them with its roles reversed. The first real test of 0.8.0 with a published Notepad worked, and showed what this release fixes: an empty window of the control over a whole monitor, the main window always shown, ten seconds lost before the program started, and a normal end shown as an error.

## What happens now

- In the session, Send to, My PC (UltimateRDP), the tray menu entry "Send files to my PC..." and `UltimateRDP.Agent.exe --send <paths>` send files and folders to your computer. They arrive in your Downloads folder, or in `receiveFolder` of client.json, never replace a file, and get the mark that Windows gives to downloads. A window shows the progress, with Cancel, and Open folder at the end. When the direct connection cannot be used, nothing is sent and the window says why.
- `UltimateRDP.exe file.rdp` with a RemoteApp file shows only the windows of the program, a notification icon, and a small "Connecting to..." window until the program appears. UltimateRDP exits by itself once the session ended. `--show` and `--hidden` choose otherwise, and a second start hands its file to the copy that runs.
- In RemoteApp mode the control no longer shows a window of its own, the tab of a shown main window holds the name of the program, its number of windows and a Disconnect button, the program starts at the logon, and the end of the session at the close of its last window is a normal end.
- Drop targets go only on the windows of the program, not on the window of the control or the proxy of the agent.
- File, Always ask for the password, the option `--ask-credentials` and the line `prompt for credentials:i:1` of the .rdp file make the client ask for the password instead of using a saved credential.
- Every line of the agent log gives its session, and the agents of one user in several sessions no longer get in the way of each other on the log file.

## Behaviour change

A .rdp file that holds `prompt for credentials:i:1` now asks for the password, even when Windows keeps a saved credential for the server; 0.8.0 used the credential. Remove the line, or set it to 0, to get the saved credential back.

## Upgrade

Install 0.9.0 on both sides. Sending files needs both sides at 0.9.0 and the ports of the direct connection open, as for large files; through a Remote Desktop Gateway it cannot work. None of the changes of this release ran against a real server before it: please send me both logs of a first send and of a first RemoteApp program opened from a shortcut. The section "Version 0.9" of the design lists the log lines that tell what works.
