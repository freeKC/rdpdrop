This release measures the transfer of large files. It does not make it faster.

## Why

With 0.4.3, large files reach the session at 2.1 to 2.6 MB/s, whatever the chunk size, on a connection that carries at least 12 MB/s. Before changing anything, I want to know which side holds the transfer back: the Remote Desktop control on your computer, the agent in the session, or the Remote Desktop connection between them.

## What changed

- At the end of each transfer, the client log says how long the client spent inside its calls to the Remote Desktop control, and how long the agent took to acknowledge the data, with the bytes on their way at that moment.
- At the end of each transfer, the agent log says how many reads of the channel it made, how large they were, how long it waited for data and how long it spent on it.
- Once per connection, the agent log gives the client address and what Windows counts about the connection.
- The client setting `transferWindowBytes` in `%LOCALAPPDATA%\UltimateRDP\client.json` sets how much data may be on its way before the agent acknowledges it: 4 MiB by default, from 1 MiB to 32 MiB.
- The agent setting `channelRead` in `%LOCALAPPDATA%\UltimateRDP\agent.json` can be set to `file` to try another way of reading the channel. It goes back to the usual way by itself, with a warning in the log, if anything looks wrong.

The README explains the new log lines under "Measuring a slow transfer".

## Upgrade

Install 0.4.4 on both sides to get the full picture. Nothing changes in what the two sides say to each other, so a 0.4.4 client works with an older agent and the other way round; each side then logs only its own lines.

If a transfer is slow for you, I would like both logs of one transfer with the default settings, and of a second one with `transferWindowBytes` set to 16777216.
