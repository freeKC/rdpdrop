This release lets one .bat file open a connection without a .rdp file, writes such .bat files for you, and fixes a RemoteApp launcher clicked a second time.

## Fixed

- With 0.9.3, a RemoteApp launcher clicked again while its program ran, or in the seconds after its last window closed, opened a second connection with the same account. Windows gives a user one session per server, so the second connection took the session of the first, and then ended: both were gone, an error showed, and the program did not start. The log of the user showed it:

  ```
  16:33:31.951 first window of the program
  16:33:38.157 A second start hands ...remoteapp...rdp to this one
  16:33:39.551 session 1: OnDisconnected reason=3 extended=5 (replaced by another connection)
  16:33:39.912 session 2: OnConnected
  16:33:42.107 session 2: OnDisconnected reason=2 extended=12 (logged off by the user)
  ```

  Now, as the Microsoft client does, a RemoteApp launch to the server, port, gateway and account of a RemoteApp tab that runs starts its program on that connection, at once or right after its logon, with a loader of its own. A launch that waited opens its own connection if the shared one ends first. Opening a desktop again while it runs selects its tab. A session taken over by another connection says so in its own words, and messages no longer pile up.

## Why

A .bat file per published program is how UltimateRDP reaches end users, so that starting a program stays one double click. Until now each .bat file needed a .rdp file written by hand beside it.

## What is new

- `UltimateRDP.exe` takes the connection on its command line: `--server`, `--port` (3389 by default), `--user`, `--domain`, `--remoteapp`, `--remoteapp-name`, `--remoteapp-args`, `--gateway`, and the display and redirection choices `--multimon`, `--scale`, `--windows-keys`, `--clipboard`, `--drives`, `--printers`, `--audio`. With a .rdp file, the options win over its keys. The README section "Launchers" lists them with the .rdp keys they set.
- `--help` or `/?` shows the list of the options in the language of the client.
- Every value is checked before anything opens. A wrong option shows a message that says which one and why, and nothing connects.
- There is no option for a password, on purpose: Windows uses the credential saved for the server, or asks for it.
- A second start hands its options to the UltimateRDP that already runs.
- File, Create a launcher (.bat)... writes a launcher: a .bat file with every option, or a .bat file and a .rdp file beside it, with UltimateRDP.exe at the path of the running program, next to the launcher, or at a path with variables such as `%LOCALAPPDATA%`. It fills itself from the active tab or from a .rdp file, shows the text of the .bat file as you type, and can save it, copy it, or test it.
- `--trusted`, and "Do not show the Windows warning (trusted server)" in the generator, off by default: no Windows warning about the publisher and the shared resources before a RemoteApp program opens, for that launch only. No key of a .rdp file can do it, and the question about the certificate of the server is not affected.
- The product shows its brand "UltimateRDP by Aprogsys" in the loader, the About dialogs, the tooltips of the notification icons and the launchers; files, processes and folders keep the name UltimateRDP.
- The loader comes back above other applications, without taking the keyboard, after a dialog it hid for is answered.
- The agent notes once, as information, a session whose client does not offer its channel, such as the Windows client, instead of a warning about a policy.
- The README gives a command to widen the scheduled task of RemoteApp sessions that works, and a way to check what the scheduler stored.
- The README starts with the measured rates of the parallel direct transfer, has a table of contents, documents every option and setting, and shows the loader, the launcher generator, the progress windows, the main window and the menus in images drawn by the application with sample data. It is translated into French, German, Spanish, Italian, Dutch and Portuguese, with images in each language.
- The values in a launcher are quoted so that cmd.exe gives them to UltimateRDP exactly and cannot run anything else. The tests check this with a model of cmd.exe and with cmd.exe itself, including hostile values.

## Not offered

Full screen at the start and a fixed desktop size: the client starts every session in its window and sizes the desktop to the window, as before.

## Upgrade

The client changes, and the agent only in one line of its log and the brand of its About dialog and tooltip. The protocol does not change. Existing .bat files and .rdp files work as before.
