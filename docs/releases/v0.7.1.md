This release frees the direct connection at once after a cancelled transfer, and tells you when a file takes long to open.

## Why

The first production test of 0.7.0 carried 255 to 296 MB/s over eight connections, but after each cancel the agent kept the direct connection busy for about 25 seconds, so the next drops went through the channel at about 2 MB/s. The transfer itself ended at once; the agent only freed the connection after it had closed and deleted the partial file in the staging folder, and on the server that took 24.8 seconds. The same test also showed a 3.6 GB executable that took 22.6 seconds to open on the client, with nothing in the progress window but "Preparing...".

## What happens now

- The agent frees the direct connection as soon as the transfer ends, whatever the deletion of the partial files takes; the deletion goes on in the background. Over loopback the connection is free 17 ms after a cancel, and a new transfer can start right away.
- The agent log gives a line with the time it took to close and delete the files, so that the next log says which step is slow on the server.
- When a file takes more than 2 seconds to open or to give its first data, the progress window and the status bar say "Opening ... Windows may be checking the file." until it is read.

## Upgrade

Install 0.7.1 on both sides; the protocol of 0.7.0 does not change, so either side also works with the other at 0.7.0. The fix of the release is in the agent, the new text in the client.
