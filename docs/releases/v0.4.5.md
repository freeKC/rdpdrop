This release keeps the fast transfer of large files when you release the button quickly.

## What happened

I dragged a file of 700 MB onto the session and released the button about a third of a second after the drag entered it. The agent answered the start of the drag, and offered the fast transfer, a few hundredths of a second after the release. The client had already sent the drop, so the remote Explorer copied the file through drive redirection at 3.7 MB/s, with its own copy dialog, next to the progress window of UltimateRDP. The fast transfer never ran.

## The fix

When you release the button before the agent answered the start of the drag, the client now waits for that answer, for at most a second and a half, and the progress window says "Preparing..." meanwhile.

- When the agent offers the transfer, the files go through the UltimateRDP channel, as if you had released the button later.
- When the agent accepts the drag without a transfer, the drop goes out as before.
- When the agent refuses the drag, the window and the status bar say why.
- When the agent does not answer in time, the drop goes out as before, through drive redirection.

During that short wait, a new drag over the session is refused as during a transfer, and the Cancel button of the window gives the drop up. The client log has one line that says how long the drop waited and what was decided.

## Upgrade

Only the client changes. Install the 0.4.5 client; the agent can stay at 0.4.4 in the session.
