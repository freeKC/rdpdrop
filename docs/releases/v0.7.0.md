This release sends large files over several TCP connections at once through the direct connection, and logs where the time of a transfer goes.

## Why

The first production test of 0.6.0 reached 135 to 180 MB/s for a few seconds, then fell to about 20 MB/s. A raw TCP test on the same path, without TLS, disk or files, showed the same curve on one connection, while four connections together filled the whole upload of the client for a few seconds and then kept about four times the rate of one. The limit is per connection, somewhere on the path, so the transfer now uses several.

## What happens now

- The client opens one connection per started 32 MiB of the transfer, eight at most by default. The files go by blocks of 1 MiB over all of them, and the agent writes each block where it belongs and checks the SHA-256 of every file as before.
- A connection that cannot be opened is not an error: the others carry the files. Before the first data is acknowledged, a failure still sends the files through the channel, as in 0.6.0.
- Cancel now closes everything within about a second, even when a connection or the read of a file is stuck, and the agent logs it as cancelled instead of a warning.
- The progress window keeps "Preparing..." until the agent acknowledged the first data. The client logs any file whose opening or first read takes more than half a second, which I suspect for the drop that moved nothing in the first test.
- Both logs end a direct transfer with a statistics line: connections, bytes per connection, where the time went, and the rates of the first and the last 5 seconds. With `logLevel` at `debug`, both log the rate of every second.

## For administrators

The firewall rules of 0.6.0 do not change: all the connections of a transfer use its port. Two new settings of agent.json: `directConnections`, 8 by default, and `directMaxMegabytesPerSecond`, 0 by default for no limit, to protect a busy server. client.json has `directConnections` too. The README explains how to read the statistics lines.

## Upgrade

Install 0.7.0 on both sides: the direct connection now speaks version 2 of its protocol. A client 0.6.0 with an agent 0.7.0, or the other way round, sends the files through the channel, at once and without an error. Over loopback I measured 2 GB in about 6.4 s over one connection and 3.9 s over eight; please send me both logs of a transfer on your network, with the statistics lines.
