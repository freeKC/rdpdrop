This is the first test release of RdpDrop. It lets you drag files or folders from your desktop and drop them into a Remote Desktop session, at the place where you release the cursor. The copy itself goes through the standard drive redirection.

The release contains two zips:

- `RdpDrop.Client-v0.1.0-win-x64.zip`: the client you run on your own computer. It opens your .rdp file and hosts the Microsoft Remote Desktop control. It is a single portable executable, with nothing to install.
- `RdpDrop.Agent-v0.1.0-win-x64.zip`: the small agent that runs in your session on the server. It receives the drop and copies the files with the usual Windows copy dialog.

Both are self contained 64 bit executables, so no .NET runtime is needed.

I built this release so that it can be tested against real servers. The shared logic is covered by unit tests, but some parts can only be confirmed in a real session.

## Install

1. On the server, unzip the agent to a folder every user can read, such as `C:\Program Files\RdpDrop`.
2. From an elevated prompt, run `"C:\Program Files\RdpDrop\RdpDrop.Agent.exe" --install-all-users`, or `--install` for your own account only.
3. On your computer, unzip the client anywhere. Make sure your .rdp file redirects drives (Local Resources, More, Drives).
4. Run `RdpDrop.Client.exe path\to\connection.rdp`, log on, wait for "Agent ready" in the status bar, then drop.

## What I could not verify yet

**The byte model of the channel.** The Microsoft control passes channel data as strings, and how it turns bytes into characters is not documented. RdpDrop detects both possible models at run time. Both the client log and the agent log have a line that contains "Channel byte model". If the agent never becomes ready, these lines and the client lines that contain "Received" are what I need to see.

**The folder under the cursor.** The agent looks for the Explorer window or the desktop under the cursor when you release it. If the files land in the fallback folder instead of the folder you aimed at, the agent log has a line for the drop that names what it found under the cursor and the target folder. The client log has a matching line with the coordinates before and after scaling.

## Logs and feedback

Both logs are in `%LOCALAPPDATA%\RdpDrop\logs`: `client-yyyyMMdd.log` on your computer, and `agent-yyyyMMdd.log` on the server. The client opens this folder from Help, Open log folder, and the agent from its tray menu.

Whether it works for you or not, please open an issue at https://github.com/freeKC/rdpdrop/issues and attach both log files. A short description of your setup helps too: Windows versions on each side, and whether you connect through a gateway.

Thank you for taking the time to try RdpDrop.
