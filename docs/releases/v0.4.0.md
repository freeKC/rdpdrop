This release makes the drop of large files faster.

## Fast transfer of large files

When you drop a file, the remote application reads it through drive redirection, in blocks of 64 KB with one round trip over the network per block. I measured 3.6 MB/s this way on a connection that carried at least 9.7 MB/s upstream: the latency, not the link, was the limit.

UltimateRDP now sends large files through its own channel instead, as a continuous stream, before the drop. The drag over the session works as before, with the feedback of the remote application. When you release the button, the status bar shows the progress, for example "Transferring 3 file(s): 42 % (12.3 MB/s, 1 min left)". Once every file is in the session, the agent drops the copies where you released the button, and the status bar says "Dropped on ..." as usual. The agent checks the size and the SHA-256 checksum of every file, and drops nothing when one does not match. Session, Cancel the transfer stops a transfer in progress.

The copies go to `%LOCALAPPDATA%\UltimateRDP\staging` in the session and are deleted one hour after the drop. The agent first checks that the disk of the session has room for the files plus 10 percent.

The agent decides with two settings in `agent.json`:

- `fastTransfer`: `auto` (the default) sends the files through the channel when the dropped items hold at least `fastTransferMinBytes`; `always` does it for every drop; `never` keeps drive redirection, as in 0.3.0. The agent tray menu has the same choice under "Fast transfer of large files".
- `fastTransferMinBytes`: 10485760 bytes (10 MiB) by default, only editable in the file.

Drive redirection must still be on, since the drag over the session uses it. The client and the agent must both run 0.4.0 for the fast transfer; with an older client or agent, every drop goes through drive redirection as before.

Both logs end each transfer with a summary line: files, bytes, seconds and MB/s. I would like to hear the rate you get on your connection.
